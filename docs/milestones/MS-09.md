## 1. Tujuan Milestone
Membangun pengelolaan kas kecil (*petty cash*) outlet dengan aturan batas bertingkat dan akumulasi harian (§6.8), alur mode ketat (*strict mode*), verifikasi Finance dengan jurnal pembalik, pencatatan biaya pusat dengan penandaan tag outlet vs pusat, serta **alur formal tutup hari (End of Day / EOD)** per outlet yang mencakup hitung kas laci, verifikasi penjualan harian, dan ringkasan operasional.

---

## 2. Checklist Tugas (Tasks)

### Sub-Fase MS-09A: Kas Kecil Outlet & Meter Batas
- [ ] **T-09.1 Skema Kontrak & Service Kas Kecil**
  - [ ] Endpoint: `GET /petty-cash/accounts`, `GET/POST /petty-cash/expenses`, `/topups`, `/limits/preview`.
  - [ ] Invariant kategori non-stok: Pengeluaran kas kecil dilarang menggunakan kategori yang terkait bahan stok (`422 validation_error`). Belanja bahan wajib melalui PO (MS-07).
  - [ ] Invariant saldo: Saldo kas kecil tidak boleh bernilai negatif (`422 insufficient_balance`).
- [ ] **T-09.2 Fungsi Domain Tingkat Kas Kecil (§6.8)**
  - [ ] Evaluasi batas per transaksi dan akumulasi harian per outlet per `business_date` (WIB).
  - [ ] Ambang seed: Tingkat 1 ≤ Rp100.000 per transaksi & ≤ Rp300.000 per hari (bebas); Tingkat 2 > Rp100.000 s/d Rp1.000.000 (Finance/Owner); Tingkat 3 > Rp1.000.000 (Owner).
  - [ ] Transaksi pukul 23:30 WIB dan 00:10 WIB dihitung pada hari bisnis berbeda.
- [ ] **T-09.3 Handler Mock Mode Ketat & Jurnal Pembalik**
  - [ ] Mode ketat: Transaksi di atas batas bebas wajib melalui alur `requested` → `approved` → `spent` (unggah nota) → `verified`.
  - [ ] Penolakan verifikasi Finance membuat **entri pembalik** untuk mengembalikan saldo kas kecil.
- [ ] **T-09.4 Halaman Akun & Saldo Kas Kecil (`PG-pc-accounts`)**
  - [ ] Daftar akun kas kecil per outlet, riwayat mutasi, form top-up dana.
- [ ] **T-09.5 Form Pengeluaran dengan Meter Batas (`PG-pc-expense-form`)**
  - [ ] Visualisasi meter batas: "Terpakai hari ini Rp X dari batas Rp Y".
  - [ ] Indikator tingkat persetujuan dan tombol "Ajukan persetujuan" jika nominal di atas batas bebas.
  - [ ] Unggah foto nota wajib, nominal > 0.
- [ ] **T-09.7 Antrean Verifikasi Finance (`PG-pc-verify`)**
  - [ ] Viewer foto struk/nota, tombol Setuju / Tolak (alasan wajib, otomatis membalik saldo).
- [ ] **T-09.8 Hitung Kas Fisik (`PG-pc-counts`)**
  - [ ] Pencatatan fisik uang kas, hitung selisih terhadap saldo sistem.

### Sub-Fase MS-09B: Biaya Pusat & Kategori Biaya
- [ ] **T-09.9 Pencatatan Biaya Pusat (`PG-cost-entries`)**
  - [ ] Entri biaya operasional pusat (sewa, gaji, listrik, marketing) dengan tag `outlet` atau `hq`.
  - [ ] Tag `hq` tidak masuk perhitungan laba outlet individual, namun muncul di konsolidasi pusat.
- [ ] **T-09.10 Master Kategori Biaya (`PG-cost-categories`)**
- [ ] **T-09.11 Integrasi Lencana & Kartu Dashboard**
  - [ ] Kartu `petty_cash` (Finance) dan `sm_petty_cash` (Store Manager), lencana `petty_cash.pending_verification`.

### Sub-Fase MS-09C: Alur Tutup Hari (End of Day / EOD)
- [ ] **T-09.13 Skema Kontrak EOD**
  - [ ] Endpoint: `GET /eod/status?outlet_id=&date=`, `POST /eod/complete`, `GET /eod/summary?outlet_id=&date=`.
- [ ] **T-09.14 Alur EOD Store Manager (`PG-eod-close`)**
  - [ ] Checklist tutup hari per outlet pada `business_date` (WIB):
    - [ ] **Hitung kas laci**: input nominal fisik uang tunai di register; selisih terhadap penjualan tunai + saldo awal laci.
    - [ ] **Verifikasi penjualan**: ringkasan otomatis omzet hari ini, jumlah transaksi, void/refund, komposisi pembayaran (tunai/QRIS).
    - [ ] **Waste tercatat**: konfirmasi semua waste hari ini sudah diinput (atau "tidak ada waste").
    - [ ] **Kas kecil tercatat**: konfirmasi pengeluaran kas kecil hari ini sudah diinput.
    - [ ] **Catatan shift** (opsional): catatan bebas dari SM untuk laporan harian.
  - [ ] Tombol "Selesaikan Tutup Hari" hanya aktif jika seluruh checklist minimal terpenuhi.
  - [ ] Setelah EOD selesai, status outlet berubah menjadi `closed` untuk hari itu dan tidak dapat di-reopen (kecuali Owner).
- [ ] **T-09.15 Ringkasan Harian (Daily Close Summary)**
  - [ ] Halaman `PG-eod-summary`: rekap otomatis per outlet per hari: omzet, HPP estimasi, laba kotor, kas laci (selisih), waste, kas kecil, dan catatan shift.
  - [ ] Dapat dicetak / diekspor PDF.
  - [ ] Riwayat ringkasan harian dapat dilihat oleh Owner, Admin, dan Finance.
- [ ] **T-09.16 Integrasi EOD dengan Dashboard & Kartu `outlet_ops_status`**
  - [ ] Kartu `outlet_ops_status` menampilkan status EOD: "Sudah tutup" vs "Belum tutup" per outlet.
  - [ ] Item `action_center` SM: "Tutup hari belum dilakukan" jika sudah melewati jam operasional.

- [ ] **T-09.12 Uji Paritas Kontrak & Skenario PRD A5**

## 3. Kriteria Penerimaan (Acceptance Criteria)

- [ ] **AC-09.1** Skenario tabel 6.8 menghasilkan tingkat persetujuan yang sama persis di UI meter batas dan mesin mock.
- [ ] **AC-09.2** Pengeluaran Rp150.000 langsung ditolak dengan pesan "butuh persetujuan"; tombol ajukan membuat permintaan di inbox Finance & Owner.
- [ ] **AC-09.3** Pengeluaran Rp1.200.000: hanya Owner yang berhak menyetujui.
- [ ] **AC-09.4** Transaksi pukul 23:30 WIB dan 00:10 WIB dihitung pada hari bisnis yang berbeda pada clock deterministik.
- [ ] **AC-09.5** Memilih kategori bahan stok ditolak saat pencatatan kas kecil.
- [ ] **AC-09.6** Menolak pengeluaran saat verifikasi Finance mengembalikan saldo kas kecil via entri pembalik.
- [ ] **AC-09.7** Pengeluaran yang membuat saldo kas kecil menjadi minus ditolak sistem.
- [ ] **AC-09.8** Biaya pusat dengan tag `hq` tidak muncul di perhitungan laba per outlet, tetapi muncul di laporan total pusat.
- [ ] **AC-09.9** Store Manager tidak dapat melihat Biaya Pusat maupun akun kas kecil outlet di luar tugasnya.
- [ ] **AC-09.10** SM dapat menyelesaikan EOD hanya jika checklist minimal terpenuhi (kas laci dihitung, penjualan terverifikasi).
- [ ] **AC-09.11** Selisih kas laci = (uang fisik di register) − (saldo awal + penjualan tunai − pengeluaran tunai) tercatat dan tampil di ringkasan harian.
- [ ] **AC-09.12** Setelah EOD selesai, kartu `outlet_ops_status` dan `sm_eod_status` berubah menjadi "Sudah tutup".
- [ ] **AC-09.13** Ringkasan harian (daily close summary) menampilkan angka yang konsisten dengan kartu dashboard dan laporan penjualan pada hari yang sama.
- [ ] **AC-09.14** SM tidak dapat melihat atau menutup hari untuk outlet di luar tugasnya (Store Manager multi-outlet Sari dapat menutup hari secara terpisah untuk Jodi Dago dan Jodi Gubeng).
