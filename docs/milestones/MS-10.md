## 1. Tujuan Milestone
Membangun alur usulan menu baru atau override resep lokal oleh Store Manager (SM) melalui wizard 5 langkah dengan simulasi HPP dan margin, alur tinjauan Admin Pusat (dengan penyuntingan harga final dan cakupan), visualisasi perbedaan (DiffViewer), dan aktivasi otomatis menu saat tanggal berlaku tercapai.

---

## 2. Checklist Tugas (Tasks)

### Sub-Fase MS-10A: Wizard Usulan Menu Store Manager
- [ ] **T-10.1 Skema Kontrak & Service Usulan Menu**
  - [ ] Endpoint: `GET/POST /menu-proposals`, `GET/PUT /menu-proposals/{id}`, `/actions/submit|withdraw|approve|reject|request-revision|promote`.
  - [ ] State machine: `draft → submitted → approved | rejected | revision_requested → active`.
  - [ ] SM hanya dapat membuat usulan untuk outlet tugasnya dan tidak dapat melihat usulan outlet lain.
- [ ] **T-10.3 Wizard Usulan 5 Langkah (`PG-prop-wizard`)**
  - [ ] Langkah 1: Info menu (nama, kategori, deskripsi, foto).
  - [ ] Langkah 2: Varian & usulan harga jual.
  - [ ] Langkah 3: Modifier (pilihan dari master modifier).
  - [ ] Langkah 4: Resep (komposisi bahan, waste %) + **Panel Simulasi HPP & Margin**.
  - [ ] Langkah 5: Ringkasan usulan & tombol Kirim / Simpan Draft.
- [ ] **T-10.4 Pratinjau HPP & Margin di Wizard**
  - [ ] Menghitung HPP menggunakan biaya rata-rata (`avg_cost`) outlet pengusul.

### Sub-Fase MS-10B: Tinjauan Admin, DiffViewer & Promosi Menu
- [ ] **T-10.2 Handler Mock Transisi Usulan ke Katalog Menu**
  - [ ] Persetujuan Admin (`menu_proposal` → `hq_admin`) secara otomatis membuat entitas menu/varian/resep baru dengan cakupan outlet dan `effective_from`.
  - [ ] Menu berstatus `active` saat `clock.now()` mencapai tanggal `effective_from`.
  - [ ] Perubahan resep setelah aktif wajib melalui usulan baru jenis `change` (tidak ada edit langsung).
- [ ] **T-10.5 Layar Tinjauan Admin Pusat (`PG-prop-review`)**
  - [ ] Kemampuan Admin menyunting usulan sebelum menyetujui: menetapkan harga final, cakupan (outlet itu, beberapa outlet, atau global), dan tanggal berlaku.
  - [ ] Tombol Setujui / Minta Revisi (alasan wajib) / Tolak (alasan wajib).
- [ ] **T-10.6 Penampil Perbedaan (DiffViewer) bagi Store Manager**
  - [ ] Memperlihatkan perbandingan antara data yang diusulkan SM vs versi final yang disetujui Admin.
- [ ] **T-10.7 Daftar Usulan, Lencana & Notifikasi**
  - [ ] Halaman `PG-prop-list`, kartu dashboard `sm_proposals`, dan lencana `catalog.proposals_pending`.
- [ ] **T-10.8 Uji Paritas Kontrak & Skenario Usulan Menu**

## 3. Kriteria Penerimaan (Acceptance Criteria)

- [ ] **AC-10.1** Budi (Store Manager Jodi Senopati) tidak dapat membuat usulan untuk outlet lain; Sari (Store Manager multi-outlet Seduhan Kopi Jodi) dapat membuat usulan untuk Jodi Dago atau Jodi Gubeng.
- [ ] **AC-10.2** Panel pratinjau di wizard menampilkan nilai HPP dan margin yang sama persis dengan editor resep pusat untuk komposisi bahan yang sama.
- [ ] **AC-10.3** Jika Admin mengubah harga usulan, Store Manager melihat visualisasi perbedaan (diff) pada rincian keputusan.
- [ ] **AC-10.4** Usulan yang disetujui dengan `effective_from` besok belum tampil di menu kasir hari ini, dan otomatis tampil saat clock dimajukan ke hari esok.
- [ ] **AC-10.5** Setelah menu aktif, upaya mengubah resep mewajibkan pembuatan usulan `change` baru (edit langsung dicegah).
- [ ] **AC-10.6** Alur revisi (Admin minta revisi → SM perbaiki → kirim ulang) menaikkan nomor revisi dokumen.
- [ ] **AC-10.7** Menarik kembali (*withdraw*) usulan setelah diputuskan oleh Admin ditolak sistem.
